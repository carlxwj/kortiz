# Collaboration, conventions et contributions

- Préférer de petites demandes de modification isolées, accompagnées de tests et d'une description des impacts utilisateurs.
- Ne jamais envoyer de données personnelles de test, clés privées, tokens ou captures contenant identifiants dans une PR ou une issue.
- Maintenir la documentation et les tests à jour à chaque modification des interfaces, schémas, règles ou commandes.
- Valider le comportement réel dans l'environnement approprié avant de déclarer une fonctionnalité terminée.
- **Pas de licence open source accordée par défaut** : contacter le mainteneur avant redistribution du code ou des médias.
- Pour toute contribution utilisant un assistant de programmation, vérifier manuellement les modifications et être capable d'expliquer les décisions techniques et les limitations.
